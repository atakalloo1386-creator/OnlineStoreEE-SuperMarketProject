# رابط کاربری سادهٔ آموزشی

صفحهٔ `/index.html` از همان WAR بک‌اند ارائه می‌شود؛ صفحهٔ ریشه به آن هدایت می‌کند.
HTML، CSS با Bootstrap RTL و JavaScript معمولی استفاده شده است.
Node.js، framework، package نصب‌شدنی یا build جداگانهٔ frontend وجود ندارد.

## فایل‌ها

| فایل | وظیفه |
|---|---|
| `js/core/api.js` | درخواست‌های /api/v1، پوشش پاسخ، خطا، upload/download |
| `js/core/ui.js` | DOM، فرم، تبدیل مقدار ورودی و نمایش داده |
| `js/modules.js` | مسیرها، فیلدها، ستون‌ها، فیلتر و actionها |
| `js/app.js` | اتصال اجزای مشترک و navigation |
| `css/app.css` | تغییرات کوچک روی Bootstrap RTL |

base API نسبت به document محاسبه می‌شود؛ context path غیر ROOT هم حفظ می‌شود.
index.html را از سرور باز کنید، نه با file://؛ همان origin برای API لازم است.
Bootstrap از CDN دریافت می‌شود؛ حالت آفلاین در این نمونه آماده نشده است.

## افزودن ماژول دانشجویی

۱. در resources یک تعریف با `id`، `group`، `title`، `path`،
`fields` و `columns` اضافه کنید.
۲. نام فیلدها دقیقاً مطابق Request باشد؛ اگر خروجی نام دیگری دارد `source` مشخص کنید.
رابطه‌ها با شناسهٔ عددی وارد شوند، نه entity.
۳. در حالت عادی GET/POST روی collection و PUT/DELETE روی /{id} استفاده می‌شود.
`paged: true` فقط وقتی /page واقعی وجود دارد.
۴. `scope` برای پارامتر لازم در مسیر مانند itemId یا ticketId و
`filters` برای query اختیاری است.
۵. `actions` شامل suffix مسیر و method است؛ `input` اختیاری یک شناسهٔ عددی می‌پرسد.
۶. `canEdit: false` و `canDelete: false` برای append-only،
`single: true` برای پروفایل و `readOnly: true` برای backend ناتمام هستند.

زیرساخت fetch جدید در هر صفحه نسازید. امنیت و validation سمت server همچنان ضروری‌اند.

## وضعیت اتصال هر گروه

| گروه | آنچه UI آماده دارد | محدودیت backend / بررسی باقی‌مانده |
|---|---|---|
| محصولات | محصول، دسته‌بندی و فیلتر | mapping active/isActive و خواندن Lazy |
| کاربران | کاربر، نقش و پروفایل | سرویس پروفایل و update/delete نقش ناقص‌اند |
| سازمان | سازمان، شعبه، دپارتمان و کارمند | تست business/cache و مجوزها اجرا نشده |
| سفارش | CRUD و عملیات وضعیت | DTO entity-based، مبلغ/اقلام/پرداخت و ارسال ناقص‌اند |
| انبار | CRUD، low-stock و ثبت گردش | ۱۸ تست entity ناموفق؛ خواندن Lazy بررسی شود |
| تیکت | CRUD و GET/POST پیام | paging/close/filter در API موجود نیست؛ Request ساده شود |
| ارسال | پیک، مرسوله و ارسال/تحویل | مقدار اولیه و guard وضعیت تکمیل شود |
| مالی | ۸ فهرست و ساختار فرم غیرفعال | سرویس/APIهای نوشتن ناتمام؛ لیست واقعی نیز ممکن است خالی باشد |
| پیوست | metadata، فیلتر مالک و upload/download | بررسی HTTP فایل و اجرای مجوز در server لازم است |

## نکته‌های استفاده

- جست‌وجوی متن فقط روی ردیف‌های بارگذاری‌شده است، نه کل database.
- هنگام فیلتر collection، paging غیرفعال می‌شود.
- ویرایش User برای تطبیق نام نقش با roleIds، فهرست /roles را می‌خواند؛ رمز لازم است.
- فرم Order مطابق قرارداد فعلی از فیلد JSON تو‌در‌تو استفاده می‌کند؛
  پس از اصلاح DTOهای backend باید metadata آن هم اصلاح شود.
- پیوست ابتدا metadata را ذخیره، سپس فایل را به /attachments/{id}/content ارسال می‌کند.
- safeJson فیلدهای حساس شناخته‌شده را در نمایش جزئیات پنهان می‌کند؛
  این کار جای حذف دادهٔ حساس از response backend را نمی‌گیرد.
- Swagger UI فقط در صفحهٔ docs بارگذاری می‌شود و برنامهٔ اصلی bundle آن را نمی‌گیرد.
